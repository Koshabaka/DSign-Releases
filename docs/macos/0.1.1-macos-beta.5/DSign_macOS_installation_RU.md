# Установка DSign на macOS

Инструкция для **DSign 0.1.1-macos-beta.5** — предварительной версии для **macOS 14 Sonoma и новее**. Релиз опубликован 9 ноября 2026 года. Инструкция проверена 10 ноября 2026 года.

[Открыть страницу этой версии на GitHub](https://github.com/Koshabaka/DSign-Releases/releases/tag/v0.1.1-macos-beta.5)

> **Перед началом.** У этой версии нет подписи Apple Developer ID и нотарификации Apple: используется подпись ad hoc. Сборка, установка из DMG и запуск интерфейса прошли автоматические проверки, но работа с КриптоПро CSP и физическим Рутокен Lite на Mac ещё не подтверждена отдельной аппаратной проверкой. Первое подписание выполняйте на нейтральном тестовом файле; сохраняйте доступ к уже проверенному способу подписания документов.

## 1. Версия macOS и процессор

В левом верхнем углу экрана откройте меню **Apple  → «Об этом Mac»**. Посмотрите версию macOS и название чипа или процессора.

| Что показано в окне | Какой файл нужен |
| --- | --- |
| **Чип Apple**, например Apple M1, M2, M3, M4 или другой чип Apple | **arm64 — Apple Silicon** |
| **Процессор Intel**, например Intel Core i5, Core i7 или Xeon | **x64 — Intel** |

Не выбирайте файл только по названию «MacBook» или году выпуска: встречаются модели с разными процессорами. Ориентируйтесь на сведения в «Об этом Mac». Это соответствует [рекомендации Apple по определению чипа](https://support.apple.com/ru-ru/116943).

**Минимальное требование — macOS 14.0.** На macOS 13 и более ранних версиях этот выпуск не поддерживается. Наличие более новой macOS само по себе не подтверждает совместимость установленного КриптоПро: её проверяют отдельно по документации производителя.

Среда **.NET включена в DSign**. Для установки готового DMG отдельно устанавливать .NET SDK, Xcode или средства разработки не требуется.

## 2. Загрузка нужных файлов

Откройте [релиз 0.1.1-macos-beta.5](https://github.com/Koshabaka/DSign-Releases/releases/tag/v0.1.1-macos-beta.5) и при необходимости разверните список **Assets**. Скачайте **два файла для одной архитектуры**: образ `.dmg` и соответствующий файл `.dmg.sha256`.

| Ваш Mac | Образ приложения | Контрольная сумма |
| --- | --- | --- |
| Apple Silicon | [DSign-macOS-0.1.1-macos-beta.5-arm64.dmg](https://github.com/Koshabaka/DSign-Releases/releases/download/v0.1.1-macos-beta.5/DSign-macOS-0.1.1-macos-beta.5-arm64.dmg) | [arm64.dmg.sha256](https://github.com/Koshabaka/DSign-Releases/releases/download/v0.1.1-macos-beta.5/DSign-macOS-0.1.1-macos-beta.5-arm64.dmg.sha256) |
| Intel | [DSign-macOS-0.1.1-macos-beta.5-x64.dmg](https://github.com/Koshabaka/DSign-Releases/releases/download/v0.1.1-macos-beta.5/DSign-macOS-0.1.1-macos-beta.5-x64.dmg) | [x64.dmg.sha256](https://github.com/Koshabaka/DSign-Releases/releases/download/v0.1.1-macos-beta.5/DSign-macOS-0.1.1-macos-beta.5-x64.dmg.sha256) |

Сохраните оба файла в одну папку — например, **«Загрузки»**. Дождитесь окончания загрузки. Если браузер показывает содержимое `.sha256` как текст, сохраните именно этот текстовый файл с исходным именем и расширением `.sha256`, без добавления `.txt` и без сохранения веб-страницы в HTML.

Пункты **Source code (zip)** и **Source code (tar.gz)** не являются установщиками. Файлы `.exe` предназначены для Windows. Для Mac с чипом Apple выбирайте arm64: устанавливать Intel-сборку через Rosetta для этой инструкции не нужно.

## 3. Проверка SHA-256

SHA-256 — контрольная сумма содержимого файла. Проверка позволяет установить, совпадает ли загруженный DMG с опубликованным значением. Она **не подтверждает личность разработчика, отсутствие вредоносного кода или нотарификацию Apple**. Поэтому проверяйте и адрес источника: `github.com/Koshabaka/DSign-Releases`.

### Основной способ: проверить по файлу .sha256

1. Нажмите **Command ⌘ + пробел**, введите **«Терминал»** или **Terminal** и откройте приложение.
2. Если оба файла сохранены в «Загрузки», выполните команду:

```bash
cd "$HOME/Downloads"
```

3. Выполните **одну** команду, соответствующую вашему Mac.

**Apple Silicon — arm64:**

```bash
shasum -a 256 -c "DSign-macOS-0.1.1-macos-beta.5-arm64.dmg.sha256"
```

Ожидаемый результат:

```text
DSign-macOS-0.1.1-macos-beta.5-arm64.dmg: OK
```

**Intel — x64:**

```bash
shasum -a 256 -c "DSign-macOS-0.1.1-macos-beta.5-x64.dmg.sha256"
```

Ожидаемый результат:

```text
DSign-macOS-0.1.1-macos-beta.5-x64.dmg: OK
```

Эти команды только читают файлы. Пароль администратора и `sudo` не нужны. Не добавляйте в команду знак `$` перед `shasum` и не копируйте строки с ожидаемым результатом.

Если файлы лежат в другой папке, введите в Терминале `cd`, затем пробел, перетащите эту папку из Finder в окно Терминала и нажмите Enter. После этого выполните нужную команду `shasum`.

**Продолжайте установку только при результате `OK`.** При `FAILED` или несовпадении суммы остановитесь, удалите ошибочно загруженные файлы и скачайте оба заново со страницы этой версии. Не смешивайте arm64 и x64 или файлы разных выпусков.

### Дополнительный способ: сравнить сумму вручную

Если файл `.sha256` не удаётся сохранить, вычислите сумму самого DMG. Из папки с файлом выполните соответствующую команду:

```bash
shasum -a 256 "DSign-macOS-0.1.1-macos-beta.5-arm64.dmg"
```

или для Intel:

```bash
shasum -a 256 "DSign-macOS-0.1.1-macos-beta.5-x64.dmg"
```

Сравните **все 64 символа** перед именем файла с нужной строкой таблицы. Здесь приведены значения DMG из метаданных GitHub Releases API, проверенные 10 ноября 2026 года:

| Архитектура | SHA-256 образа DMG |
| --- | --- |
| arm64 | `c776b42d52a7d82b82e89cb27a592ebc9f762d1c712320aee3d654591cb75e14` |
| x64 | `130d6f39c4905def7cc44935408716e5a3a3ef59bbe3e301b35f084356fa4983` |

Эти суммы относятся **только к 0.1.1-macos-beta.5**. Для другой версии берите её собственный `.sha256`. В API у файла `.sha256` есть отдельный digest — это сумма текстового файла, её нельзя использовать вместо суммы DMG.

## 4. Установка приложения

После успешной проверки SHA-256:

1. Откройте скачанный `.dmg` двойным щелчком в Finder.
2. В появившемся окне перетащите **DSign.app** на значок **Applications — «Программы»**. Если значка нет в поле зрения, откройте папку «Программы» в Finder и скопируйте приложение туда.
3. Дождитесь завершения копирования. Если macOS запрашивает разрешение на запись в эту папку, подтвердите его своей учётной записью или обратитесь к администратору компьютера.
4. Закройте окно образа. В боковом меню Finder нажмите значок извлечения рядом с диском **DSign**.
5. Откройте **Finder → «Программы» → DSign**.

Запускайте установленную копию из «Программ», а не приложение внутри подключённого DMG. Если установлена предыдущая версия DSign, сначала завершите её работу; при осознанном обновлении подтвердите замену приложения.

## 5. Первый запуск без нотарификации Apple

Подпись **ad hoc** не удостоверяет разработчика сертификатом Apple Developer ID. Нотарификация — отдельная автоматическая проверка Apple; у этой версии её нет. Поэтому при первом запуске возможно предупреждение о неизвестном разработчике или невозможности проверить приложение на вредоносное ПО.

Если источник и SHA-256 проверены и вы принимаете ограничения бета-версии, используйте штатное разрешение **для DSign**:

1. Попробуйте открыть DSign из «Программ».
2. Закройте предупреждение кнопкой **«Готово»**, **«ОК»** или отменой.
3. Откройте **Apple  → «Системные настройки» → «Конфиденциальность и безопасность»**.
4. Прокрутите до раздела **«Безопасность»** и найдите сообщение именно о DSign.
5. Нажмите **«Всё равно открыть» / Open Anyway**. В отдельных русских переводах кнопка называется **«Подтвердить вход»**.
6. Подтвердите открытие и, если macOS попросит, введите пароль входа в Mac. Это не PIN Рутокена.

Исключение сохраняется для приложения. Такой порядок описан в [инструкции Apple](https://support.apple.com/ru-ru/102445). Ручное разрешение не заменяет нотарификацию и не служит гарантией безопасности.

**macOS 15 Sequoia и новее:** не рассчитывайте на обход предупреждения через Control‑клик → «Открыть». Apple изменила этот механизм; используйте «Конфиденциальность и безопасность». [Сообщение Apple об изменении](https://developer.apple.com/news/?id=saqachfa).

Для этой установки не отключайте Gatekeeper, SIP или XProtect и не удаляйте карантинные атрибуты командами из интернета. Если штатное разрешение недоступно, разберите причину по разделу ниже.

> **Другое предупреждение — другое действие.** При сообщении «повредит вашему компьютеру», обнаружении вредоносного ПО или сообщении о повреждённом приложении не применяйте этот порядок разрешения запуска. См. отдельные строки в таблице ошибок.

## 6. Подготовка к работе с электронной подписью

Запуск интерфейса DSign и готовность компьютера подписывать документы — разные этапы. Для подписания и проверки ГОСТ используются установленные компоненты КриптоПро.

Подготовьте:

- **КриптоПро CSP для macOS**, совместимый с вашей версией системы и процессором. Для подписания нужна действующая лицензия CSP, в том числе допустимая пробная, если она предоставлена производителем. [Официальная загрузка CSP](https://cryptopro.ru/products/csp/downloads).
- **КриптоПро ЭЦП Runtime — компоненты CAdES для macOS**. Одного расширения браузера недостаточно: DSign использует настольные утилиты КриптоПро. [Официальная загрузка компонентов ЭЦП](https://www.cryptopro.ru/products/cades/downloads). Для загрузок может потребоваться учётная запись КриптоПро.
- **Личный сертификат ГОСТ со связью с закрытым ключом** в личном хранилище КриптоПро текущего пользователя. Простого наличия файла `.cer` или записи в «Связке ключей» macOS недостаточно.
- **Сертификаты удостоверяющего центра и сведения об отзыве**, необходимые для проверки доверия. Настраивайте их по инструкции своего УЦ.
- **Подключённый носитель и его настройку**, если ключ хранится на Рутокене. Используйте инструкции именно для своей модели. Не устанавливайте драйвер Рутокен S по аналогии, если у вас Рутокен Lite. [Документация производителя по работе с КриптоПро на macOS](https://dev.rutoken.ru/pages/viewpage.action?pageId=72451200).

Сначала убедитесь средствами КриптоПро, что система видит носитель, контейнер и личный сертификат. Затем откройте DSign и нажмите **«Обновить»** у списка сертификатов.

PIN вводите только в штатном окне КриптоПро. Не вставляйте его в команды, отчёты или сообщения разработчику. Если провайдер предлагает только консольный ввод PIN, эта версия DSign не сможет завершить такую операцию.

Работа DSign с конкретной комбинацией Mac, macOS, CSP, CAdES и Рутокен Lite **остаётся неподтверждённой до проверки на реальном оборудовании**. Официальная совместимость компонентов между собой ещё не доказывает совместимость всей связки с DSign.

## 7. Пробное подписание

После настройки криптокомпонентов проверьте работу на своём Mac:

1. Создайте отдельную папку и нейтральный файл, например `test.txt` с текстом «Проверка DSign». По возможности используйте тестовый сертификат.
2. На экране **«Подписать»** нажмите **«Добавить файлы»**, добавьте этот файл и выберите нужный сертификат. Проверьте владельца и срок действия сертификата.
3. Нажмите **«Подписать»**. При запросе введите PIN в окне КриптоПро. По умолчанию подпись сохраняется рядом с оригиналом; другую папку можно выбрать через **«Папка подписей…»**.
4. Убедитесь, что появился `test.txt.sig`. На экране **«Проверить»** выберите исходный `test.txt` и соответствующий файл `.sig`, затем нажмите **«Проверить подпись»**. Проверьте отдельно результаты **целостности**, **доверия к сертификату** и **отзыва сертификата**.
5. Проверьте ту же пару независимым средством КриптоПро. Для дополнительной проверки измените содержимое копии исходного документа: прежняя подпись не должна подтверждать целостность изменённого файла.

Сохраните вместе документ и его отделённую подпись. После подписания не редактируйте исходный документ: подпись относится к его конкретному содержимому. Не приравнивайте успешную проверку целостности к подтверждённому доверию к сертификату.

## 8. Ошибки и способы их устранения

### Загрузка, установка и запуск

| Сообщение или ситуация | Что делать |
| --- | --- |
| `No such file or directory`, `FAILED open or read` при проверке суммы | Проверьте текущую папку и наличие **обоих** файлов. Имена должны совпадать с указанными в `.sha256`: браузер мог добавить `(1)` или `.txt`. Удобнее заново скачать пару в пустую папку с исходными именами. |
| `no properly formatted SHA checksum lines found` | Вместо файла суммы мог сохраниться HTML или другой текст. Скачайте настоящий `.sha256` из Assets либо сравните сумму вручную по разделу 3. |
| `FAILED` или другая сумма DMG | Не открывайте образ. Заново скачайте DMG и `.sha256` одной версии и архитектуры. Если расхождение повторяется, остановитесь и сообщите разработчику. |
| DMG не открывается, «образ повреждён», `image not recognized` | Убедитесь, что загрузка завершена, проверьте SHA-256. При несовпадении скачайте заново; если сумма совпадает, а образ всё равно не открывается, сохраните точный текст ошибки и обратитесь к разработчику. |
| «Приложение не поддерживается на этом Mac», значок перечёркнут | Сверьте macOS 14+ и архитектуру. На Intel нужен x64, на Apple Silicon — arm64. Если на Apple Silicon запрашивается Rosetta, прежде всего проверьте, не скачан ли x64. |
| «Разработчик не может быть проверен», Apple не может проверить приложение | При проверенном источнике и совпавшем SHA-256 используйте раздел 5. Это отличается от прямого сообщения об обнаруженном вредоносном ПО. |
| DSign «повреждён и не может быть открыт» | Не считайте это обычным отсутствием нотарификации. Удалите неработающую копию приложения, скачайте релиз заново, проверьте сумму и повторите копирование. Если сообщение остаётся — прекратите запуск и обратитесь к разработчику; не переподписывайте приложение и не снимайте карантин. |
| «Повредит вашему компьютеру», обнаружено вредоносное ПО или приложение перемещено в Корзину защитой macOS | Не разрешайте запуск и не восстанавливайте эту копию ради обхода блокировки. Сообщите разработчику точное предупреждение. Apple рассматривает такие сообщения отдельно от неизвестного разработчика. |
| Нет кнопки Open Anyway | Ещё раз попробуйте открыть установленный DSign и сразу проверьте «Конфиденциальность и безопасность», прокрутив до «Безопасность». Если Mac управляется организацией или изменение запрещено, обратитесь к её администратору. При повторяющейся блокировке сохраните её текст. |
| Приложение закрывается сразу или просит установить .NET | Убедитесь, что используете готовый DMG этой версии, а не исходники, и запускаете копию из «Программ». Перепроверьте архитектуру и сумму, переустановите копированием. Среда .NET уже включена; если проблема остаётся, нужен отчёт разработчику. |

Различия между предупреждениями о разработчике, повреждении и вредоносном ПО описаны в [справке Apple о безопасном открытии приложений](https://support.apple.com/ru-ru/102445).

### Подписание и проверка

| Сообщение или ситуация | Что делать |
| --- | --- |
| Не найдена утилита `certmgr` или `cryptcp` | Проверьте установку CSP и компонентов ЭЦП Runtime для macOS. Эта версия DSign ожидает утилиты по путям `/opt/cprocsp/bin/certmgr` и `/opt/cprocsp/bin/cryptcp`. Не копируйте отдельные исполняемые файлы из случайных сборок. |
| Не удалось запустить утилиту КриптоПро | Проверьте совместимость установленных компонентов с архитектурой Mac и версией macOS, затем работоспособность средствами самого КриптоПро. |
| Список сертификатов пуст, носитель не найден | Проверьте носитель и сертификат в КриптоПро под той же учётной записью. Нужен личный сертификат со связью с ключом. Переподключите носитель, при возможности исключите USB-хаб и нажмите «Обновить» в DSign. |
| Подписание ждёт PIN или завершается по тайм-ауту | Найдите окно КриптоПро: оно может быть позади DSign. Проверьте подключение токена. Если окно не появилось, отмените операцию и проверьте настройку провайдера. Консольный ввод PIN эта версия не поддерживает. |
| Ошибка лицензии, срока сертификата или доверия | Проверьте лицензию CSP, срок действия и назначение сертификата, дату и время Mac, цепочку УЦ и доступность служб отзыва. Не исправляйте это отключением защиты macOS. |
| Статус отзыва недоступен | Проверьте сеть и доступность служб УЦ. Этот результат не означает, что сертификат не отозван. Не включайте опцию разрешения при неизвестном статусе отзыва только ради устранения сообщения. |
| «Нет доступа к файлу или папке» | Выберите доступную локальную папку для теста и сохранения подписи. Убедитесь, что исходный файл полностью загружен из облака и папка доступна для записи. Не выдавайте полный доступ ко всему диску как универсальное решение. |
| Документ превышает 64 МиБ | Для этой версии предел одного исходного файла — **64 МиБ (67 108 864 байта)**. Выберите меньший тестовый файл. Произвольное разбиение юридически значимого документа может изменить смысл результата. |
| Подпись не проходит проверку | Сверьте, что выбраны соответствующие документ и `.sig` и документ не менялся после подписания. Различайте нарушение целостности и проблемы доверия или отзыва. Сохраните оригинальную пару для независимой проверки. |

## 9. Ограничения бета-версии

| Область | Что известно для 0.1.1-macos-beta.5 |
| --- | --- |
| Статус выпуска | Предварительная версия — prerelease/beta. Возможны ошибки; её не следует делать единственным способом срочного подписания. |
| Сборки и установка | Доступны отдельные DMG для arm64 и x64. Автоматически проверены сборка, установка из образа и запуск трёх экранов интерфейса. |
| Версии macOS | Заявлен минимум macOS 14. Автоматическая проверка интерфейса выполнялась на macOS 15; это не проверка всех более новых и более старых поддерживаемых конфигураций. |
| Подпись приложения | Ad hoc; Apple Developer ID и нотарификация Apple отсутствуют. Проверка SHA-256 этого не меняет. |
| КриптоПро и Рутокен Lite на Mac | Полная аппаратная проверка не завершена. Автоматические тесты логики используют имитацию ответов КриптоПро и не доказывают работу с реальным носителем. |
| Другие конфигурации | Не подтверждены все сочетания версий CSP/CAdES, моделей токенов и сертификатов, работа x64-сборки через Rosetta, виртуальные машины и удалённый USB-проброс. Отсутствие подтверждения не равно установленной несовместимости. |
| Формат результата | Создаётся отдельный файл подписи `.sig`. Это не видимая подпись внутри PDF. Ограничение исходного файла — 64 МиБ. |
| Результат проверки | Успех в DSign не гарантирует приём подписи конкретным судом, порталом или информационной системой. Требования получателя и независимую проверку нужно учитывать отдельно. |

Документы обрабатываются локально, однако проверки сертификатов средствами КриптоПро могут обращаться к службам УЦ. Полностью автономная проверка доверия и актуального статуса отзыва без доступа к необходимым данным не обещается.

## 10. Обновление, удаление и сообщение об ошибке

**Обновление.** Для ручного обновления завершите DSign, скачайте новый macOS-релиз нужной архитектуры, проверьте **его** контрольную сумму и замените DSign.app в «Программах». При необходимости снова пройдите штатное разрешение первого запуска. Не рассчитывайте на автоматическое обновление по аналогии с Windows. Перед обновлением сохраните документы и подписи.

**Удаление.** Завершите DSign и переместите DSign.app из «Программ» в Корзину. Удаление приложения не требует удаления сертификатов, контейнеров ключей, КриптоПро или данных на Рутокене. Документы и подписи храните отдельно от приложения.

**Сообщение об ошибке.** Передайте разработчику через указанный на сайте приложения канал поддержки:

- версию DSign, точное имя DMG и результат проверки SHA-256;
- модель Mac, тип процессора и версию macOS;
- точный текст ошибки, этап её появления и шаги воспроизведения;
- при проблемах подписания — версии CSP/CAdES, модель токена и результат проверки носителя средствами КриптоПро;
- снимок экрана после удаления персональных данных, сведений о доверителях и конфиденциальных имён файлов.

Не публикуйте PIN, пароли, закрытые ключи, контейнеры и рабочие документы. Для воспроизведения проблемы по возможности используйте нейтральный тестовый файл. Полные системные журналы отправляйте только после проверки их содержимого.
